# Portfolio API v1
Envelope and string IDs match Teaching API. Base `/api/v1/portfolio`. Staff uses `student:read`/`student:write`; own-family reads validate academic relationships live.
- GET `/records?themeId=&studentId=` -> Record[]; POST `/records` DraftInput -> Record; GET `/records/{id}` -> Record; PUT `/records/{id}` DraftInput -> Record.
- DraftInput `{version?:number,themeId:string,studentId:string,progress:"NOT_STARTED"|"IN_PROGRESS"|"MAKEUP_PENDING"|"COMPLETED",classroomNote:string,comment:string,artworks:[{id:string,title:string,kind:"PROCESS"|"FINAL",mediaIds:string[],participantIds:string[],story:string}],audioMediaIds:string[]}`.
- Record `{id,version:number,branchId,status:"DRAFT"|"PUBLISHED"|"WITHDRAWN",content:DraftInput,createdAt}`. Staff draft edits separate from immutable published snapshots. Parent list/detail exposes ONLY currently published snapshot, never current draft. Participant IDs must include record student; all collaborators same branch and staff accessible.
- POST `/records/{id}/publish` `{version:number,idempotencyKey:string}` -> Publication; POST `/records/{id}/withdraw` `{version:number,reason:string}` -> Record. Publication `{id,recordId,version:number,content:DraftInput,createdAt}`. Each reissue new immutable publication.
- GET `/themes/{themeId}/roster` -> [{studentId,name,recordId:string|null,progress,status}]; GET `/dashboard?branchId=` -> `{draft:number,published:number,withdrawn:number,makeupPending:number}`.
- GET `/students/{id}/growth` -> `{studentId,publications:Publication[],assessments:Assessment[],reports:Report[]}`.
- POST `/students/{id}/reports` `{title:string,summary:string,publicationIds:string[]}` -> Report `{id,studentId,title,summary,publications:Publication[],createdAt}`.
- GET/POST `/students/{id}/assessments` with `{stageId,assessedAt:"YYYY-MM-DD",scores:{[dimensionCode]:number},comment}` -> Assessment `{id,studentId,stageId,stageCode,stageName,assessedAt,assessedBy,scores,comment,createdAt}`. Legacy `/api/students/{id}/stage-assessments` supported.
- POST `/publications/{id}/consent` `{allowed:boolean,displayName:string}` -> `{publicationId,allowed}`. Only actual guardian, staff cannot grant. Revocation invalidates new public reads immediately.
- GET `/exhibitions` -> Exhibition[]; POST `/exhibitions` `{title,introduction,publicationIds:string[]}` -> Exhibition; POST `/exhibitions/{id}/approve` `{}` -> Exhibition; POST `/exhibitions/{id}/withdraw` `{}` -> Exhibition. Exhibition `{id,title,introduction,status:"DRAFT"|"PUBLISHED"|"WITHDRAWN",createdAt}`. Approval requires `exhibition:approve` or super admin. GET `/api/v1/portfolio/public/exhibitions` -> published Exhibition[]; GET `/api/v1/portfolio/public/exhibitions/{id}` -> `{exhibition,works:[{publicationId,displayName,artworks:[{title,kind,mediaIds,story}]}]}`. No student IDs, private notes, household comment, or collaborator identities in public payload. Works without current consent omitted.
- POST `/records/{id}/media-access` `{mediaIds:string[]}` -> media access result from media-service; only IDs contained in authorized current snapshot/draft accepted.

Additional integration details:
- Public image access: GET `/public/exhibitions/{id}/publications/{publicationId}/media-access?mediaIds=id1,id2` -> `{items:[{id,url,expiresAt}]}`. It rechecks published exhibition, fixed publication, every collaborator's guardian consent and live academic family membership before signing. GET is required for visitor access.
- Writes accept `portfolio:write` as a scoped alternative to legacy `student:write`; only reads use `student:read`.
- Withdrawal permanently revokes all existing publication versions of that record. Reissue creates a new ID requiring new public consent and cannot resurrect an explicitly withdrawn public version.
- Teacher list visibility uses academic bulk authoritative access; dashboards aggregate all authorized records, independent of the 100-row list limit.
- Events target `notification`, types `portfolio.published` and `portfolio.withdrawn`; payload `{recordId,publicationId,studentId,branchId,title,version}`. Withdraw version is the updated record revision.
- `PUT` leaves existing published household snapshot visible while a staff member edits the separate current draft. Record response top-level `version` is the optimistic concurrency value; don't use `content.version` for the next write.

## Review additions

- Record and roster rows add `needsPublishing:boolean`, independent of `status`; dashboard adds total `needsPublishing`. Editing a published draft sets it true; explicit final publication clears it. Parent record responses never reveal private draft state.
- Record lists scan a stable descending `(createdAt,id)` keyset until enough authorized rows have been found. Unauthorized recent rows don't consume the requested limit. Theme rosters load every matching existing record, including classes above 100 students.
- POST `/publications/{id}/media-access` `{mediaIds}` signs only files in that fixed published snapshot. POST `/reports/{reportId}/publications/{publicationId}/media-access` also verifies the report includes that snapshot. Both recheck the current family/student authorization and reject explicitly revoked publications after reissue.
- GET `/records/{id}/entries`, GET `/students/{id}/entries` -> Entry[]. Parents see only independently `PUBLISHED` classroom updates, even before a final record publication. Teachers see all statuses.
- POST `/records/{id}/entries` `{lessonId,occurredAt:ISO,notes,mediaIds:string[],idempotencyKey}` -> Entry `{id,recordId,lessonId,occurredAt,notes,mediaIds,status:DRAFT|PUBLISHED|WITHDRAWN,createdAt}`. Entries are append-only; a correction is a new entry. The lesson must belong to that teaching theme at append time; already recorded entries remain after theme scheduling changes. Supplement lessons first extend the teaching theme's lessonIds.
- POST `/records/{id}/entries/{entryId}/publish` `{idempotencyKey}`; POST `/records/{id}/entries/{entryId}/withdraw` `{reason}`. Retries don't emit repeated classroom notifications. Withdrawn entries cannot be republished; create a correction.
- POST `/records/{id}/entries/{entryId}/media-access` `{mediaIds}` -> signed media items after live family and explicit entry visibility checks.
- GET `/records/{id}/history` -> staff audit array `{id,actorId,action,reason,content,createdAt}`; includes immutable edit, final publish, entry append/publish/withdraw records.
- GET `/students/{id}/collections`, POST `/students/{id}/collections` `{title,summary,publicationIds}` -> curated collection(s) shaped like Report. Teachers and approved families can select that child's fixed published versions. Collections remain private; withdrawal removes invalid selections from later reads. Use publication media access for their files.
- Exhibition create adds optional `startsAt`/`endsAt` UTC timestamps; response includes them. Future exhibitions are hidden publicly; ended exhibitions are presented as archived and remain discoverable subject to current consent. POST `/exhibitions/{id}/archive` requires approval authority and an already approved exhibit. Withdrawal still hides the entire exhibit.
- GET `/public/exhibitions/{id}/publications/{publicationId}/certificate` and GET `/public/exhibitions/{id}/share-card` -> `{svg:string,filename:string}`. SVG output escapes text, uses no external scripts/images, and is suitable for export. Certificate creation checks every collaborating child's current consent. Existing exported files cannot be retroactively erased.
- All media reference updates now use local transactional Outbox events `portfolio.media-references`, target `media`, payload `{ownerType,ownerId,mediaIds,revision}`. Local transaction rollback removes the event; media handles duplicate/out-of-order owner revisions. Media usability is checked synchronously before starting the local business transaction. Image signing may briefly return retryable pending/not-ready while the committed reference event is delivered.

V1 media limit: each saved/published draft counts all artwork media plus audio together and permits at most **100 unique media IDs**. The same total applies to a classroom entry and a report/curated collection's selected snapshots. Exceeding it returns HTTP 400, `单次内容最多关联 100 个不同媒体文件（含音频）`, before saving or enqueuing reference events. Every reference event deduplicates IDs. Historical transferred-student roster rows include the same actual `needsPublishing` boolean as current students.

## Media provenance authorization

New media references must belong to the authenticated uploader, unless they are already present in the record's authorized current draft or nonwithdrawn per-lesson entries. Edits and publication preserve those existing references for substitute teaching; knowing an unrelated private same-campus media ID cannot inject it into a record.

For deliberate reuse between records, POST `/records?sourceRecordId={sourceId}` and PUT `/records/{id}?sourceRecordId={sourceId}` validate the explicit source record's tenant and current student authorization. Only media already in that authorized source draft/nonwithdrawn entries can bypass uploader ownership. The request still requires destination write/student/class permissions. Omit sourceRecordId for ordinary uploads or editing retained media. Unauthorized fresh IDs fail with HTTP 403 before row or Outbox mutation. `media.usable` remains a readiness/metadata protocol; it does not by itself grant reference rights.
