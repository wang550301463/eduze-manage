# 综合美术宝：产品与 Mac 风格体验分析

分析日期：2026-09-08。代码基线：`99d0419`。本文是供讨论的产品分析与设计建议，不是已确认的实施规格。

用户已明确偏好：**柔和半透明、轻盈、有空间感**。

## 1. 核心判断

建议把产品定位为：**围绕孩子的艺术成长，连接课堂、家庭与机构经营的服务平台。**

现有 demo 的价值在教务底座：学员、家庭关系、主带老师、可用时段、课次、出勤、接送与课时记录。要成为综合美术宝，关键是补全“课堂产生作品与观察 → 家庭看见学习过程 → 孩子表达自己的创作 → 机构持续改进教学和服务”的闭环。

视觉方向建议采用“轻透工作空间”：导航与工具轻盈，阅读与作品清楚，复杂操作有稳定的位置。半透明是表现层；页面围绕人的任务组织，才会改变使用体验。

推荐**一个平台、共享业务数据、四种角色体验**。机构侧以桌面 Web 和教师移动工作流为主，家庭侧以手机为主，小朋友先通过家长陪伴模式或课堂平板参与。四种角色不意味着必须开发四个独立 App。

## 2. 分析依据与边界

本轮查看了路由、导航、样式、老师工作台、校长看板、学员详情、课次详情、出勤相关页面、后端控制器目录、迁移文件清单，以及五月总体设计与九月视觉改版文档。

README 中的本地 5173 端口实际打开了另一个项目；Docker 清单曾显示美术系统映射至 18080，但本轮浏览器访问返回连接拒绝。因此以下界面判断以当前源码为依据，**没有把运行中页面的视觉走查、任务耗时或用户访谈作为已完成证据**。建议项和假设均需在原型测试中验证；没有编造满意度、提升百分比或开发工期。

旧文档假设学员以 4–12 岁为主、1–5 个校区、家长使用微信。本文暂沿用这些规模与渠道假设。课程体系文档还包含 13–16 岁阶段，实际主力年龄段应在后续设计前核实。最新需求明确加入小朋友体验，因此早期“孩子不上手机”不能再当成排除儿童体验的约束。

## 3. 当前 demo 的具体问题

### 3.1 上一次改版的范围不足以解决本次目标

九月七日视觉规格明确“不重做信息架构、路由、权限模型”，并排除了液态玻璃背景。当前已使用系统字体优先、浅灰背景、圆角与暖色控件，这些资产可以保留。你这次选定的柔和半透明方向，则需要重新定义材质和空间层次。

真正的落差是：全站依然以管理模块为骨架。改圆角和底色能提高一致性，无法让老师自然完成课后反馈，也无法让家长理解孩子这节课学到了什么。

依据：[上一轮视觉规格](socrates/specs/2026-09-07-mac-tahoe-control-redesign-design.md)、[全局样式](../web/src/styles/globals.css)、[字体与主题](../web/tailwind.config.ts)。

### 3.2 导航把系统结构直接交给了用户

主导航有 10 个配置项，系统区还有 3 个，实际显示受权限控制。“工作台”和“我的工作台”并存，“老师可用时段”“分组标签”等配置概念与日常操作同级。首页直接挂载校长看板，尚未按角色分派。

建议老师以“今天、课表、孩子、作品、消息”为入口；老板以“总览、待办、教学、学员经营、经营数据”为入口。老师可用时段放进课表设置，分组标签在学员筛选和排课上下文中操作，系统配置统一收纳。

依据：[导航](../web/src/app/shell/nav-config.tsx)、[路由](../web/src/app/router.tsx)。

### 3.3 老师首页有统计外观，缺少任务推进

老师工作台展示本周课次、两个值为“-”的指标、维护可用时段和一组课次链接。它回答了“有多少课”，没有突出“下一节课准备什么、上一节课还差谁的反馈”。

后续浏览器验证确认了一个衔接问题：老师页链接使用 `lessonId`，但当前 `/schedule` 挂载的老师周课表没有解析课次定位参数，课次卡片本身也没有点击处理。仓库中另一个课次周课表实现读取 `openLessonId`，但它并未挂载到当前路由，不能将两者当作同一个页面。若只改视觉，该类交互断点会继续存在。

依据：[老师工作台](../web/src/features/teacher/pages/MyWorkbenchPage.tsx)、[当前周课表](../web/src/features/teacher/pages/WeeklySchedulePage.tsx)、[后续浏览器验证记录](evidence/2026-09-08-browser-verification.md)。

### 3.4 学员被呈现为档案，成长尚未成为主线

学员详情目前有“基础、家长、课时包、课时流水、出勤、请假”六个标签，位于 `sm:max-w-lg` 的抽屉内。可供快速查阅，但承载作品比较、成长记录和长期服务信息会局促。请假标签仍返回开发阶段占位说明。

建议保留轻量预览，新增独立的孩子成长主页：近期作品与课堂记录在前，课程安排与家校沟通居中，行政档案、课时和历史操作按权限收纳。需要持续编辑或对照的内容进入完整页面。

依据：[学员详情](../web/src/features/student/components/StudentDetailSheet.tsx)、[请假标签](../web/src/features/student/components/StudentLeaveTab.tsx)。

### 3.5 校长看板还不能支持完整经营决策

目前四项指标是本周缺勤人次、本月平均出勤率、本周新生、本周课次；页面主要出口是签到工作台。这是教务概览的一部分，不能据此宣称已有续费、营收、利润或客户经营能力。

老板首页需要“问题 → 原因 → 责任人 → 下一步”：哪些孩子连续缺勤、哪些反馈未完成、哪些家庭需要服务跟进、哪些时段容量利用不佳。收款和续费指标待订单、合同与资金数据具备后接入，不能用课时余额推算营收或利润。

依据：[校长看板](../web/src/features/dashboard/pages/PrincipalDashboardPage.tsx)、[出勤 KPI](../web/src/features/attendance/components/BranchAttendanceKpis.tsx)。

### 3.6 美术特色存在于规划，尚未形成用户闭环

总体设计已把课堂作品和家长端放在第二期；当前路由和所检查的后端控制器中，未找到完整的作品发布、作品集和家长自助端。顶部通知按钮明确标注为占位。不能把家长档案 CRUD 等同于家长端，也不能把课程维度数据等同于成长报告产品。

下一步应把作品归档、课堂观察、家长查看、孩子讲述放在同一条链路中完成。

依据：[总体规划](socrates/specs/2026-05-09-eduze-manage-design.md)、[顶部工具栏](../web/src/app/shell/Header.tsx)、[课程体系设计](socrates/specs/2026-05-22-teacher-centric-scheduling-design.md)。

## 4. 四类用户：分别服务，彼此连接

### 老师：帮助我把每个孩子教好，并减少课后整理

- 主要设备：课堂手机或平板；备课、批量整理使用电脑。
- 首页第一屏：下一节课、需要留意的学生信息、待完成的课后反馈。
- 课前：课程目标、材料清单、名单、请假变化、上次课堂观察。
- 课中：快速点名、拍摄过程、记录一句观察，集中在当前课堂上下文。
- 课后：批量上传 → 确认每张作品属于谁 → 共性课堂描述 → 个别反馈 → 发布预览。
- 降低负担：共性描述复用，个别反馈简短具体；支持草稿保存、上传失败单项重试和未完成名单。
- 评价效果：完成整班课后记录的总时长、重复录入次数、错配作品数。以实测建立基线。

### 家长：让我知道孩子学了什么、下次怎么安排

- 主要设备：手机；先验证现有微信渠道是否适合承载通知与入口。
- 建议底部入口：今天、成长、课表、我的。
- 首页第一屏：孩子切换、下节课时间与材料、最新课堂反馈、待处理事项。
- 反馈应包含：作品原图、学习目标、老师观察、孩子的一句话。避免只有“真棒、继续加油”。
- 常用服务：请假、补课进度、课时明细、联系机构；所有事项有当前状态和后续预期。
- 多孩子家庭共用家庭入口，进入每个孩子后保持数据边界。对不同监护人的权限按家庭授权配置。
- 评价效果：家长能否快速找出下节课、说清本次学习内容、理解请假与补课状态。

### 小朋友：让我拥有自己的作品，愿意表达创作想法

- 首期使用场景：家长陪伴查看，或课堂平板使用；独立儿童账号作为后续验证项。
- 核心入口：我的画册、我想说、灵感小任务。
- 作品可命名、收藏，选出“我最喜欢的一张”，录下创作故事；低龄儿童依靠图像和语音导航。
- 低龄以看、听、说为主；较大孩子可写创作说明、选主题和回顾阶段变化。年龄不是能力定级的唯一依据。
- 鼓励描述个人探索，如“我尝试了新的配色”；首期不做美术能力排行榜、外貌或天赋判断、强制连续打卡。
- 默认在家庭与授课范围内查看。公开展览由机构配置并获得相应授权；不默认开放陌生人评论。
- 评价效果：孩子能否找到自己的作品、愿不愿讲述创作过程；不用使用时长当主要目标。

### 老板：让我知道教学和服务是否稳定、哪里需要介入

- 主要设备：电脑做经营分析，手机查看异常与待办。
- 首页第一屏：机构/校区范围、需要处理的问题、对应责任人与行动入口。
- 教学服务：出勤变化、课后反馈完成情况、家长反馈、时段容量使用、服务跟进。
- 经营扩展：续费机会、订单收款、退费与余额核对，在数据来源完整后分阶段上线。
- 数据点击后进入可解释明细：时间范围、筛选条件、分子分母和业务事件保持一致。
- 老板与校长保留范围差异；前台、顾问、管理员继续存在于权限体系，不因四种主体验而被删除。

## 5. 产品主线：一节课如何连接四方

1. **课前**：课次关联老师、学员和课程目标；家长查看安排，老师看到请假与材料准备。
2. **课堂**：名单与实际出勤分开记录，老师采集作品和过程观察；前台保留独立接送工作台。
3. **课后**：老师批量归属作品、填写反馈；每名孩子有独立发布状态，未完成内容留在草稿。
4. **家庭**：家长只看到已发布且有权访问的内容；通知失败可重试，不影响已保存作品。
5. **孩子表达**：孩子为作品命名或讲故事，家长陪伴确认；作品进入个人成长时间线。
6. **服务改进**：机构查看反馈完成与家庭问题，安排跟进；阶段回顾复用已有课堂证据。

作品应关联孩子、课次、作者/上传者、原图、过程图、教师观察、孩子表达和可见范围。课堂教学目标与课时商品是不同概念，不宜都叫“课程”。

评估以可观察证据为依据，少用模糊的满分图。现有 778 包含元素、设计原则和艺术流派；这些分类不天然构成同一量纲的能力分数，尤其不宜直接把八种流派做成儿童能力排名。可作为教学覆盖标签，家长端使用容易理解的观察描述。

## 6. Mac 风格：具体应该怎么设计

### 6.1 三种路线与推荐

**推荐：轻透工作空间 + 作品画廊。** 半透明用于侧栏、工具栏、轻量浮层；作品和正文置于稳定、接近不透明的阅读面。既贴近你的偏好，也能支撑密集教务操作。代价是需要认真设计层级、滚动区域和性能降级。

**备选：系统设置式。** 清晰、成本相对可控，适合配置页面；当前改版已经接近这条路线，但空间感较弱，单靠它承载作品和家庭体验不够。

**备选：沉浸画廊式。** 强调作品、大图和留白，适合成长档案与家庭端；管理端若全站采用，会降低排课、批量编辑的效率。

建议统一材质、字体、图标和状态语义，再允许不同页面使用不同密度。不要把四个角色做成四套互不相关的品牌。

### 6.2 空间分层

- 环境底层：低饱和、低对比的柔和底色，可做极轻的静态色域；不采用持续运动的装饰背景。
- 导航工具层：薄磨砂侧栏和工具栏，用细边界与适量模糊明确其位置。
- 内容层：作品保持原色；文字、表格使用稳定的阅读底。避免透出的背景干扰数值和画作判断。
- 详情层：宽屏使用可收起的右侧详情区，普通查看保持列表可见；小屏进入详情页。
- 确认层：仅在有明确影响范围的操作中使用聚焦对话框，如取消课次、发布反馈。

苹果的材料指南将 Liquid Glass 定义为导航与控件的功能层，并强调与内容的层次关系；侧栏指南也提出复杂层级可用内容列表与详情组成分栏。这里借用的是这些原则，实际 Web 效果需要原型验证。[Apple Materials](https://developer.apple.com/design/human-interface-guidelines/materials)、[Apple Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars)

### 6.3 建议作为原型起点的设计参数

以下是项目设计建议，非苹果官方强制参数，必须结合设备和背景实测调整：

- 桌面侧栏约 220–240px；工具栏约 56px；正文 14–16px；触屏交互热区至少以 44px 为起点。
- 三栏仅在宽屏且主内容宽度足够时启用；中屏使用两栏，手机用单列与底部导航。
- 磨砂区域模糊约 16–24px、浅色覆盖约 75%–90%；内容面约 96%–100% 不透明。模糊强度不与高级感等同。
- 主内容面圆角约 16–20px，控件约 8–12px；间距采用稳定的小组尺度，避免所有控件胶囊化。
- 基础色以柔和中性为主，现有陶土暖色缩减为少量品牌和主操作强调；侧栏选中可用浅色填充和明确文字/图标状态。
- 字体继续系统字体优先；中文正文保留清晰字重。图标统一线性风格，避免把 emoji 和多套图标混用。
- 过渡约 160–220ms，仅在导航、选中、浮层展开等状态变化时使用；提供减少动画和减少透明度的等价体验。
- 明亮环境、小屏与低性能设备优先可读性；模糊不支持时直接使用实体背景。

### 6.4 交互规则比材质更重要

**查看有连续性。** 学员列表选择孩子后在右侧预览；进入完整成长主页后返回仍保留筛选、滚动位置和所选对象。复杂长期编辑不层层叠加抽屉。

**首页有下一步。** 老师看下一节课与未完成反馈，家长看下一次到课与最新反馈，孩子看自己的作品，老板看需要介入的事项。

**批量操作有预览。** 调课显示受影响人员和时间；发布显示孩子、作品归属与接收范围。拖拽可以辅助排课，但同时提供点击式调整入口。

**操作状态分清。** “保存草稿”“已发布”“通知送达”“已读”是不同状态；失败显示原因和下一步，不将未加载伪装成空数据。

**搜索和快捷键可复用。** 保留现有 Cmd/Ctrl+K 基础，统一实体链接参数；搜索结果直接进入对应孩子或课次，不让用户再次定位。

## 7. 技术落点：复用现有底座，分阶段扩展

继续使用现有 React、Vite、Tailwind、Radix 和 Spring Boot 模块化结构。当前任务没有证据表明需要更换框架、重写后端或拆微服务。

复用租户/校区、用户角色、学员/家庭关系、老师/可用时段、课次/名单、签到接送、课时流水。先统一角色首页、实体跳转和页面容器，再把新的课堂工作流接在现有课次上。

新增重点包括作品媒体、课后反馈、发布状态、家庭账号与监护关系授权、消息记录、成长档案聚合。媒体采用私有存储与受控访问；列表使用缩略图、原图按需读取。上传需要进度、重试和草稿恢复。

家庭账号的访问边界需要由服务端校验监护关系及授权范围，不能依靠隐藏菜单或知道 studentId。儿童模式也应有独立的数据返回范围，避免只是遮住家长页面中的账单字段。

保持“作品保存 → 反馈发布 → 通知投递”分离：通知失败允许重试，不回滚已保存内容；重复操作不能重复发布或重复通知。课堂状态、出勤与课时扣减分别保留业务语义，完成课后反馈不能再次触发扣课。

AI 可在后续辅助语音转文字、基于教师观察整理草稿、搜索教案；生成内容必须由老师复核。不自动判断孩子天赋，不从缺少证据的图片推断心理，不把未确认的生成反馈发给家长。首期体验不依赖 AI 才能完成。

## 8. 实施顺序与验收

### 第一阶段：确定体验方向与关键原型

产物：轻透设计语言、四角色首页结构、老师课堂详情、孩子成长档案、家长课后反馈。用同一节课串联这些页面，再决定全站推广。

验收：老师能找到下一节课并辨认待办；家长能找到上课信息并解释本次学习内容；小朋友能找到自己的画；老板能由问题进入可处理明细。此时先验证流程与理解，不承诺数值收益。

### 第二阶段：形成最小业务闭环

交付：现有教务 + 课堂作品批量归属 + 老师反馈草稿/发布 + 家长查看 + 陪伴式儿童画册 + 基础服务待办。家庭端与作品发布同批设计，避免出现“有端无内容”或“有内容无人接收”。

验收：权限隔离、作品归属、重复提交、上传失败恢复、撤回后访问、通知失败重试、家长多孩子切换、手机操作均有完整路径。用一班真实规模的数据验证老师总工作量，不能靠单个样例宣称高效。

### 第三阶段：成长与经营深化

交付：阶段回顾、服务跟进、经营数据口径、招生试听与订单收款等。儿童独立使用、开放展览、复杂互动及 AI 能力另行验证。

衡量建议：先跟踪“实到学员中，课后作品与有效反馈按机构约定时限发布的比例”和教师完成耗时；家长查看是触达信号，不等同满意度。长期观察留存/续费与教学体验的关系，不能直接当作因果提升。

经营指标必须注明范围与口径：出勤率基于应到和实到规则，续费率基于明确定义的到期人群，满班率区分预约和实际到课；没有财务数据就不展示利润。

## 9. 下一轮设计优先确认的事项

本文已可用于选择产品方向。进入实施前，需要核实：主力年龄段、老师实际使用设备、家庭入口渠道、首先试点的校区与班型，以及家长最重视的反馈内容。建议通过老师完成一次真实课后整理、家长查看一次课堂反馈的任务观察来确认。

首个设计单元建议确定为：**老师今日工作台 → 课堂作品与反馈 → 家长课堂回顾 → 小朋友个人画册**。这条链路同时验证美术产品价值、老师负担和轻透视觉，结论成熟后再扩展老板经营页与全站。
