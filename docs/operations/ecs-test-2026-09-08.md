# SunnyDraw 单 ECS 测试环境

用户确认使用单台 ECS，Docker 部署全部服务、MySQL、Redis，由 Nginx 转发。此环境用于联网测试；微信真机、支付、容量和灾难恢复验收仍需分别完成，不能视为正式业务上线验收。

**访问限制：** 用户确认域名备案正在办理或尚未办理。公网 HTTP 请求被阿里云返回 `403 Non-compliance ICP Filing`，没有进入 Nginx；ECS 本机访问入口返回正确的 301 HTTPS 跳转。部署时公网 HTTPS 页面、登录和接口验证通过，但备案完成前不能保证云平台持续放行，也不能将 HTTP 访问验收标为通过。备案或接入备案完成后必须重新检查公网入口。

## 部署配置

- 入口：`https://www.sunnydraw.com`，ECS `47.116.178.217`。仅配置 `www` 域名，裸域名没有配置 DNS。
- 主机：Alibaba Cloud Linux 4.0.5，Linux amd64，4 核、约 7.3 GiB 内存、40 GB 系统盘。
- 容器：Docker 28.3.3，Compose 2.26.1，项目名 `eduze-sunnydraw-test`。
- 八个业务服务：identity、academic、teaching、portfolio、media、notification、engagement、commerce。另有 web、gateway、mysql、redis，共 12 个容器。
- Java 服务使用 `prod` 配置及真实 OSS，关闭本地媒体适配。此配置名表示运行适配器，不改变环境的测试用途。
- 在 Mac 上为 `linux/amd64` 重新构建九个应用镜像，连同三种基础镜像，经 SSH 上传并加载。启动时不在 ECS 拉取或构建应用镜像。
- 镜像版本：`20260908-ecs-test-1`。归档 SHA256：`acb02ce21a7d9b23c068e827832d96c461cf3cb76056c97e00ca97b1c48354b3`。各镜像 ID 记录在发布目录的 `images.json`。
- MySQL 与 Redis 使用持久卷、私有容器网络，不映射主机端口；外部入口为 80、443，SSH 为 22。
- 每个 Java 容器限制 640 MiB，MySQL 1 GiB，Redis 256 MiB，web/gateway 各 128 MiB。Docker 日志使用 `local` 驱动，每文件 20 MB，保留五份。

## 目录与凭证

- `/opt/eduze/releases/20260908-ecs-test-1/`：Compose、初始化脚本、镜像归档、镜像清单及验收工具。
- `/opt/eduze/current`：通过验收后的当前发布目录。
- `/opt/eduze/shared/platform.env`：独立数据库口令、Redis ACL 口令、内部调用凭证、管理员初始化信息和 OSS 凭证；仅 root 可读。
- `/opt/eduze/shared/nginx.conf`：HTTPS 入口和业务服务路由。
- `/opt/eduze/shared/certs/server.crt`、`server.key`：用户已申请的阿里云证书及私钥，仅 root 可读。
- `/opt/eduze/shared/payment-keys/`：支付密钥挂载目录，目前为空。
- `/opt/eduze/backups/`：数据库备份与独立临时容器恢复验证结果。

管理员使用单独生成的 `studio-admin` 账号，不复用本地开发密码。本机交付的登录信息在用户私有目录 `~/.config/eduze/deploy-sunnydraw/access.txt`；口令、云密钥及证书私钥不进入 Git、镜像和本文。

`mysql-init.sh`、`redis-start.sh` 不包含实际口令，设置为 0644，允许容器内专用账号读取。MySQL 官方入口会切换为 `mysql` 用户再执行初始化脚本，不能将脚本误设为仅宿主机 root 可读。环境文件和证书私钥继续保持 0600。

## HTTPS 与 OSS

Nginx 使用从阿里云证书管理下载的现有 DigiCert 证书，证书包含 `www.sunnydraw.com`，到期时间为 **2026-12-06 23:59:59 UTC**。需在阿里云续期后替换证书文件并验证、重载 Nginx；当前没有配置自动续期任务。准备过程中另申请的 Let's Encrypt 证书未被网关使用，也没有启用其续期任务。

Bucket `sunnydraw` 保持私有。`OSS_ENDPOINT` 为 `https://oss-cn-shanghai-internal.aliyuncs.com`，供 ECS 校验和封存文件；`OSS_PUBLIC_ENDPOINT` 为 `https://oss-cn-shanghai.aliyuncs.com`，供签发浏览器、小程序可访问的上传和下载地址。CORS 仅允许 `https://www.sunnydraw.com`，方法 GET/PUT/HEAD，暴露 ETag 和请求 ID。媒体读取签名不超过五分钟。

## 日常操作

以下命令在 ECS 上由有 Docker 权限的账号执行。不要输出完整 Compose 解析结果或环境文件，以免将凭证写入终端记录。

```sh
docker compose --env-file /opt/eduze/shared/platform.env -f /opt/eduze/current/compose.yml ps
docker compose --env-file /opt/eduze/shared/platform.env -f /opt/eduze/current/compose.yml logs --tail 100 media
docker compose --env-file /opt/eduze/shared/platform.env -f /opt/eduze/current/compose.yml exec -T gateway nginx -t
docker compose --env-file /opt/eduze/shared/platform.env -f /opt/eduze/current/compose.yml exec -T gateway nginx -s reload
```

发布新的应用镜像时，先验证 Linux 架构和镜像归档 SHA256，再加载镜像、生成新的发布目录并修改对应镜像标签。私有配置和数据卷继续使用原路径及原 Compose 项目名。新版本健康检查及 HTTP 验收通过后更新 `current` 链接。不要执行 `down -v`；它会删除业务数据卷。

```sh
docker load -i /opt/eduze/releases/<新版本>/images-linux-amd64.tar.gz
docker compose --env-file /opt/eduze/shared/platform.env -f /opt/eduze/releases/<新版本>/compose.yml config --quiet
docker compose --env-file /opt/eduze/shared/platform.env -f /opt/eduze/releases/<新版本>/compose.yml up -d --no-build --wait --wait-timeout 300
```

需要回退时，先确认旧镜像兼容当前数据库迁移及事件版本，再使用此前发布目录更新对应服务。不能恢复旧备份来覆盖当前有效数据。单服务更新和数据库备份暂停期间可能短暂中断请求。

## 验收工具与备份

发布目录中的工具取自仓库现有脚本，仅调整了部署路径；恢复工具增加 512 MiB 内存限制和独立网络。数据库恢复检查创建随机名称的临时 MySQL 容器，逐库导入、校验摘要和逐表行数，结束后删除临时容器，不覆盖运行中的数据库。

```sh
python3 /opt/eduze/current/scripts/verify-database-isolation.py
python3 /opt/eduze/current/scripts/platform-backup.py --quiesce
python3 /opt/eduze/current/scripts/platform-restore-check.py /opt/eduze/backups/<备份时间>
```

`--quiesce` 会暂停八个业务服务，形成跨库一致的恢复点，备份后恢复服务。使用在线独立快照时不能声称形成了跨库一致恢复点。本次基线备份 `20260908T130621Z` 保存在 ECS，并已下载到用户本机私有目录 `~/.config/eduze/deploy-sunnydraw/backups/20260908T130621Z/`，再次核对 SHA256。日常自动备份及异地保留策略、OSS 版本保留及误删恢复尚未配置或验收。

## 本次部署验证

- SSH 上传的归档 SHA256 与本机构建产物一致，12 个镜像的配置摘要和 `linux/amd64` 架构逐个一致。
- 12 个容器均有健康检查；八个业务服务使用独立数据库并完成 Flyway 初始化。
- 公网 HTTPS 实际返回用户原有 DigiCert 证书，Mozilla CA 信任链和 Chrome 浏览器校验通过。
- Chrome 使用独立临时配置实际登录管理员账号，工作台加载成功，没有页面 JavaScript 异常。
- 通过真实接口上传 32×32 PNG 到私有 OSS，由 ECS 内网完成校验和封存；授权读取与原始字节一致，缩略图返回 WEBP，未签名对象访问返回 403，网站 CORS 预检通过。保留一条标有“部署验收”的私人测试课件。
- 未登录的课件与媒体访问拒绝；公网 `/internal/openapi` 和 `/actuator/health` 返回 404。
- 八个数据库账号分别能查询自己的迁移表，并拒绝访问其他服务数据库；两个 Redis 账号只允许自己的 key 前缀，拒绝跨前缀读取及全局枚举。
- 八个服务通过实际 JDBC 连接检查，JVM 与数据库会话时区均为 `Asia/Shanghai`，事件无八小时时差，课表时间往返一致。
- Docker 端口映射及 ECS 监听检查确认，仅网关绑定 80/443，业务容器、MySQL、Redis 均没有绑定主机端口。
- 八个数据库已在暂停业务服务的情况下备份，并在独立临时 MySQL 容器中恢复；文件摘要和逐表行数全部匹配。临时恢复容器已删除，运行中的数据库没有被恢复操作覆盖。
